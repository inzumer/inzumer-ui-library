## Why these choices, briefly

- **tsup over a hand-rolled Rollup/esbuild setup**: near-zero config for a "build a library, emit ESM +
  types" use case, which is all these two packages need.
- **Vitest over Jest**: shares Vite's transform pipeline (same TS/JSX handling as the rest of the
  toolchain), faster, no separate Babel config to maintain.
- **CSS custom properties over CSS-in-JS**: theming needs to work for plain CSS/Tailwind consumers
  too (see [Design Tokens](/docs/documentation-design-tokens--docs)), and avoids a runtime styling
  library as a dependency.
